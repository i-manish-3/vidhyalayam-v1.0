# Vidhyalayam ERP — Azure VM & CI/CD Master Deployment & Troubleshooting Guide

This is the definitive, production-grade deployment and operations manual for **Vidhyalayam School ERP**. It covers one-time server provisioning on **Azure Linux VM (Ubuntu 22.04 LTS)**, compulsory Redis and PostgreSQL setup, Nginx reverse proxy with SSL, PM2 process management, **automated zero-downtime CI/CD via GitHub Actions**, and step-by-step troubleshooting playbooks for production issues.

## 1. System Architecture

```text
       Internet Traffic (HTTPS 443 / HTTP 80)
                         │
                         ▼
             ┌───────────────────────┐
             │      Nginx Proxy      │ (SSL Termination, Gzip, SSE buffering off)
             └───────────┬───────────┘
                         │ Proxy Pass (http://127.0.0.1:3000)
                         ▼
             ┌───────────────────────┐
             │  PM2 Process Manager  │ (exec_mode: 'fork', auto-restart)
             └───────────┬───────────┘
                         │
        ┌────────────────┼────────────────────────┐
        ▼                ▼                        ▼
┌──────────────┐ ┌───────────────┐      ┌─────────────────────┐
│  vidhyalayam │ │ Redis Workers │◄────►│ Compulsory Redis    │
│(Next.js 16)  │ │ (4 Processes) │      │ (127.0.0.1:6379)    │
└───────┬──────┘ └───────┬───────┘      └─────────────────────┘
        │                │
        └────────┬───────┘
                 ▼
        ┌─────────────────────┐
        │ PostgreSQL Database │
        │ (127.0.0.1:5432)    │
        └─────────────────────┘
```

### Managed Processes (PM2)
The application runs 5 distinct, decoupled processes defined in [ecosystem.config.cjs](file:///c:/Manish/my-digital-acadmey/ecosystem.config.cjs):
1. **`vidhyalayam`**: Next.js 16 Web & API server running on port `3000`. Direct binary: `node_modules/next/dist/bin/next start`.
2. **`worker-demand`**: BullMQ demand slip generator worker for bulk student fee processing.
3. **`worker-notifications`**: BullMQ WhatsApp, Email, and Push notification worker.
4. **`worker-exports`**: Asynchronous Excel/CSV and PDF export job processor.
5. **`worker-audit`**: Daily audit log retention and compression worker.

## 2. Server Specifications & One-Time Azure VM Setup

### 2.1 Azure Virtual Machine
- **OS**: Ubuntu Server 22.04 LTS (x64 Gen 2)
- **Recommended VM Size**: `Standard_B2ms` (2 vCPUs, 8 GiB RAM) or minimum `Standard_B2s` (2 vCPUs, 4 GiB RAM).
- **Public IP**: Set to **Static** under Azure Public IP configuration.
- **SSH Authentication**: Ed25519 or RSA 4096-bit private key.

### 2.2 Network Security Group (NSG) Inbound Rules

| Priority | Name | Destination Port | Protocol | Source | Action | Purpose |
|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| **300** | Allow-SSH | `22` | TCP | Any / Admin IP | Allow | Secure Remote Shell |
| **310** | Allow-HTTP | `80` | TCP | Any | Allow | Web Traffic & Certbot Verification |
| **320** | Allow-HTTPS | `443` | TCP | Any | Allow | Secure Web Traffic (SSL) |

> [!CAUTION]
> **PostgreSQL (5432)** and **Redis (6379)** must **NEVER** be opened in Azure NSG inbound rules. They must strictly bind to `127.0.0.1`.

## 3. Step-by-Step Initial Server Installation

SSH into the Azure VM:
```bash
ssh -i /path/to/azure_key.pem azureuser@<AZURE_VM_PUBLIC_IP>
```

### 3.1 Install OS Packages
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y git curl unzip build-essential nginx postgresql postgresql-contrib redis-server certbot python3-certbot-nginx psmisc lsof
```

### 3.2 Enable & Verify Compulsory Redis
Redis 7+ is required for queue management and worker processing:
```bash
sudo systemctl enable --now redis-server
redis-cli ping
# Expected output: PONG
```

### 3.3 Configure 4GB Swap Space (Prevents Build OOM Crashes)
Next.js 16 builds consume significant memory. Swap prevents the Linux kernel Out-Of-Memory (OOM) killer from terminating the build with Exit Code 137:
```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Verify:
free -h
```

### 3.4 Install Node.js 22 LTS & PM2
```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
sudo npm install -g pm2
pm2 startup systemd
# Copy and run the sudo env command generated by the pm2 startup output
```

### 3.5 PostgreSQL Database Setup
```bash
sudo -u postgres psql
```
Inside the PostgreSQL shell:
```sql
CREATE USER vidhya WITH PASSWORD 'YOUR_STRONG_PASSWORD_HERE';
CREATE DATABASE vidhyalayam OWNER vidhya;
\q
```
Verify the connection:
```bash
PGPASSWORD='YOUR_STRONG_PASSWORD_HERE' psql -h 127.0.0.1 -U vidhya -d vidhyalayam -c 'SELECT 1;'
# Expected output: 1
```

### 3.6 Create Web Directory & Clone Repository
```bash
sudo mkdir -p /var/www/vidhyalayam
sudo chown -R $USER:$USER /var/www/vidhyalayam
cd /var/www/vidhyalayam

git clone https://github.com/i-manish-3/vidhyalayam-v1.0.git .
```

### 3.7 Create Production `.env`
```bash
nano /var/www/vidhyalayam/.env
```
Paste and fill with production credentials:
```env
NODE_ENV=production
DATABASE_URL=postgresql://vidhya:YOUR_STRONG_PASSWORD_HERE@127.0.0.1:5432/vidhyalayam?connection_limit=50&pool_timeout=20

# Generate 32-byte hex keys with: openssl rand -hex 32
JWT_SECRET=REPLACE_WITH_GENERATED_32_BYTE_HEX_KEY
TOKEN_ENCRYPTION_KEY=REPLACE_WITH_ANOTHER_GENERATED_32_BYTE_HEX_KEY

# Application URLs & Storage
PUBLIC_APP_URL=https://erp.vidhyalayam.com
STORAGE_DRIVER=local

# Redis Configuration (Compulsory)
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
USE_QUEUE=true

# Worker Concurrency Settings
FEE_DEMAND_GENERATE_CONCURRENCY=5
WHATSAPP_WORKER_MAX_SCHOOLS=20
WHATSAPP_WORKER_POLL_MS=1500
NOTIFICATION_QUEUE_CONCURRENCY=10
```

### 3.8 Initial Build & PM2 Launch
```bash
cd /var/www/vidhyalayam
npm install --prefer-offline --no-audit
npx prisma generate
npx prisma db push --accept-data-loss

export NODE_OPTIONS="--max-old-space-size=2048"
export NEXT_TELEMETRY_DISABLED=1
rm -rf .next
npm run build

# Start all 5 processes via PM2
pm2 start ecosystem.config.cjs
pm2 save --force
```

### 3.9 Configure Nginx Reverse Proxy & SSL
Create `/etc/nginx/sites-available/vidhyalayam`:
```bash
sudo nano /etc/nginx/sites-available/vidhyalayam
```
Paste the following configuration:
```nginx
server {
    listen 80;
    server_name erp.vidhyalayam.com;

    client_max_body_size 50M;

    # Gzip Compression
    gzip on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_buffering off; # Compulsory for Server-Sent Events (SSE)
    }
}
```
Enable the site:
```bash
sudo ln -sf /etc/nginx/sites-available/vidhyalayam /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```
Obtain SSL via Certbot:
```bash
sudo certbot --nginx -d erp.vidhyalayam.com
```

## 4. Automated CI/CD Pipeline (GitHub Actions)

Vidhyalayam uses a fully automated zero-downtime CI/CD pipeline triggered on push to **`main`** or **`test-deploy`**.

### 4.1 CI/CD Workflow (`.github/workflows/deploy.yml`)
When code is pushed to GitHub:
1. **Build Verification Job (GitHub Runner)**:
   - Installs dependencies.
   - Runs `npx prisma generate`.
   - Runs a dry-run production build (`npm run build`) to catch TypeScript or syntax errors before touching the live server.
2. **Deploy Job (Azure VM via SSH)**:
   - Connects to Azure VM using SSH private key stored in GitHub Secrets.
   - Fetches the active branch and resets hard (`git reset --hard origin/<branch>`).
   - Executes [scripts/deploy-azure.sh](file:///c:/Manish/my-digital-acadmey/scripts/deploy-azure.sh).

### 4.2 GitHub Secrets Configuration
Configure these secrets in repository **Settings** $\rightarrow$ **Secrets and variables** $\rightarrow$ **Actions**:

| Secret Name | Value Description |
|:---|:---|
| `AZURE_VM_HOST` | Azure VM Public IP (`172.198.57.21`) or domain (`erp.vidhyalayam.com`) |
| `AZURE_VM_USERNAME` | SSH username on Azure VM (`azureuser`) |
| `AZURE_VM_SSH_KEY` | Private SSH key (`~/.ssh/github_actions_azure`) |
| `AZURE_VM_PORT` | `22` |

### 4.3 Deployment Script Mechanics (`scripts/deploy-azure.sh`)
The deployment script is self-healing and performs the following sequence:
1. **Redis Verification**: Ensures `redis-server` is responding with `PONG`.
2. **Git Pull**: Fetches the latest commits and aligns the working directory.
3. **Dependencies & Prisma**: Installs packages and syncs schema via `npx prisma db push --accept-data-loss`.
4. **Cache Wipe & Next.js Build**: Cleans `.next` build cache (`rm -rf .next`) and compiles with `NODE_OPTIONS="--max-old-space-size=2048"`.
5. **Permissions**: Enforces `chmod -R 755` across `/var/www/vidhyalayam`.
6. **Port 3000 Zombie Termination**: Kills any orphaned Node processes bound to port 3000 (`sudo fuser -k 3000/tcp`).
7. **PM2 Fork Restart**: Restarts all 5 processes via `pm2 start ecosystem.config.cjs` and saves PM2 state.
8. **Automated Health Check**: Polls `/api/version` and tests static assets (`/logo.png`, `/_next/*.css`) to confirm 200 HTTP responses.

## 7. Master Troubleshooting Guide

### Issue 1: "Styles / CSS Missing, UI is Plain Text, Logo Returns 500"
- **Symptom**: The HTML loads, but all `/_next/static/chunks/*.css` and `/logo.png` return `HTTP 500 Internal Server Error` with `Content-Type: text/plain` and body `Internal Server Error`.
- **Root Cause**:
  1. An orphaned "zombie" Node process from an earlier deployment is still listening on port 3000 in memory.
  2. The files on disk were updated by `next build`, but the in-memory process is referencing older chunk manifests that no longer exist on disk.
  3. Stale Turbopack cache in `.next` was not wiped before compilation.
- **Solution**:
  ```bash
  cd /var/www/vidhyalayam
  pm2 delete all || true
  sudo fuser -k 3000/tcp || true
  sudo lsof -t -i:3000 | xargs -r sudo kill -9 || true
  rm -rf .next
  export NODE_OPTIONS="--max-old-space-size=2048"
  npm run build
  sudo chmod -R 755 .next public
  pm2 start ecosystem.config.cjs
  pm2 save --force
  ```

### Issue 2: "PM2 Process vidhyalayam in Infinite Restart Loop (↺ 150+ Restarts)"
- **Symptom**: `pm2 status` shows `vidhyalayam` with high restart count and `errored` or `launching` status.
- **Root Cause**:
  1. `ecosystem.config.cjs` configured with `script: 'npm'` in cluster mode forwarded duplicate arguments (`next start -p 3000 3000`). Next.js tried to find directory `./3000/` and crashed.
  2. Port 3000 is occupied by a background process (`EADDRINUSE: address already in use :::3000`).
- **Solution**:
  1. Ensure `ecosystem.config.cjs` uses direct binary: `script: 'node_modules/next/dist/bin/next'` and `args: 'start'`.
  2. Kill the occupant on port 3000: `sudo fuser -k 3000/tcp`.
  3. Start cleanly: `pm2 start ecosystem.config.cjs`.

### Issue 3: "Build Fails with Exit Code 137 or Out of Memory"
- **Symptom**: Next.js compilation crashes during `Creating an optimized production build`.
- **Root Cause**: The Azure B-series VM ran out of physical RAM.
- **Solution**:
  1. Check swap: `free -h`. If swap is 0, recreate 4GB swap space (Section 3.3).
  2. Set Node memory limit: `export NODE_OPTIONS="--max-old-space-size=2048"`.

### Issue 4: "502 Bad Gateway from Nginx"
- **Symptom**: Visiting the domain shows Nginx 502 Bad Gateway.
- **Root Cause**: Nothing is listening on `127.0.0.1:3000`. Next.js is down or crashed on startup.
- **Solution**:
  1. Inspect PM2 logs: `pm2 logs vidhyalayam --lines 50`.
  2. Check `.env` file exists and has valid `JWT_SECRET` (at least 32 characters) and `DATABASE_URL`.
  3. Test direct local connection: `curl -I http://127.0.0.1:3000`.

### Issue 5: "Redis Connection Refused / ECONNREFUSED 127.0.0.1:6379"
- **Symptom**: Workers crash on startup with Redis connection errors.
- **Root Cause**: `redis-server` is stopped or died.
- **Solution**:
  ```bash
  sudo systemctl restart redis-server
  redis-cli ping
  # Must output: PONG
  pm2 restart all
  ```

### Issue 6: "GitHub Actions Fails: Host Key Verification / Permission Denied (publickey)"
- **Symptom**: Workflow step `SSH and Deploy to Azure VM` fails immediately.
- **Root Cause**: Azure VM doesn't have the public key in `~/.ssh/authorized_keys`, or permissions on `.ssh` are too permissive.
- **Solution**:
  ```bash
  chmod 700 ~/.ssh
  chmod 600 ~/.ssh/authorized_keys
  # Ensure the matching public key is in ~/.ssh/authorized_keys
  ```

## 8. Emergency Rollback Procedure

If a bad commit causes regressions in production:

```bash
cd /var/www/vidhyalayam

# 1. View recent commit history
git log -n 5 --oneline

# 2. Reset to the last known good commit ID
git reset --hard <GOOD_COMMIT_HASH>

# 3. Clean cache and rebuild
rm -rf .next
export NODE_OPTIONS="--max-old-space-size=2048"
npm run build
sudo chmod -R 755 .next public

# 4. Restart PM2 cleanly
pm2 delete all || true
sudo fuser -k 3000/tcp || true
pm2 start ecosystem.config.cjs
pm2 save --force

# 5. Confirm version
curl -s http://127.0.0.1:3000/api/version
```
